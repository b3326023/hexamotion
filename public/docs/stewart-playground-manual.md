# HEXAMOTION 六軸平台完整系統手冊

手勢操控、產業應用與運動控制實驗

系統版本 3.5 · 手冊版本 3.5.0 · 更新日期 2026-11-27

HEXAMOTION 將縮尺 Stewart 平台放進瀏覽器。拖曳手勢盤，六支致動器便會伸縮，透過關節帶動載台。切換海事、飛行、結構或光學應用，可以在同一組機構上操作不同的物理問題。

首頁提供十三種民用情境與自由操控。進階工作臺提供手繪滾球、迷宮、挑戰、工程量測與影片錄製。本手冊收錄三個工作區的操作、建模假設、限制與驗證方法。可從線上手冊頁首下載整份 PDF 或 Markdown。

## 1 系統目的與整體設計

Stewart 平台用六支可伸縮致動器，共同改變上平台的位置與角度。使用者可以直接拖動平台、調整每根腿、丟球觀察碰撞，也可以讓控制器傾斜平台，將球帶回中心或沿著指定路徑運動。工作臺的迷宮、挑戰與影片輸出可記錄投球、追蹤和失敗的過程。

本專案的起點是一臺作者在大學時親手製作的小型六軸實體平台。九年後，網頁版以 AI 輔助開發，把同型別機構與控制問題帶到瀏覽器。網頁模型使用本檔案列出的模擬參數，不應把它的尺寸、負載或控制結果當作當年實體作品的量測資料。

系統適合三種使用情境：一般玩家用搖桿、路徑與關卡感受慣性和回授；教師與學生用圖形和參數理解六自由度及控制器差異；開發者以可重現的模擬步進研究功能原型、故障與演算法取捨。

### 系統功能

| 功能領域 | 使用者可以做什麼 |
|---|---|
| 應用工作室 | 操控飛行座艙、海浪補償、對接與精密對位等十三種情境，讀取個別試驗指標 |

| 遊戲 | 三個迷宮、置中衝刺、精準停球、海浪生存與節能控制 |
| 直覺操作 | 3D 拖曳投球、XY 精確投球、觸控搖桿、WASD 和方向鍵 |
| 觀察與分享 | 運動向量、成績卡、橫式或直式影片、截圖、JSON 與 CSV |

### 資料與控制流程

使用者操作 → UI 事件 → Simulation 或 PlaySession → 控制器與姿態規劃 → IK 與六腿伺服 → Rapier 剛體世界 → 量測回授 → 3D 場景及儀表。

| 層級 | 責任與關係 |
|---|---|
| React 操作層 | 收集滑桿、按鍵、路徑與遊戲意圖，不直接指定球應在哪裡 |
| 任務層 | 管理控制模式、目標選擇、遊戲生命週期、評分與資料紀錄 |
| 控制與機構層 | 根據誤差產生傾角，從六維姿態計算腿長並限制命令動態 |
| 物理層 | 根據伺服施力、重力、碰撞與摩擦更新平台和球 |
| 視覺與音訊層 | 從同一狀態繪製機構、向量、雷達、字幕與合成音效 |

控制器改變的是平台姿態。球會因重力在傾斜面上加速，接近目標時由反向傾斜減速。球可能超越目標、撞牆或掉下去，這些結果是模型允許的物理行為。

## 2 切換工作區

首頁 `index.html` 開啟應用工作室。單指拖曳控制盤可以直接操控平台，選取應用後，直接在現場畫面拖曳即可操控，旁邊的機構視窗顯示同步反應。從「精密操控」可展開該場景的專屬儀器。切換應用時保留已投入的物件。頁尾的「系統手冊」與「手勢指南」內的手冊連結提供操作與模型依據。

頂欄可直接切換「場景控制」、「遊樂場」與「工程臺」。手繪循跡、迷宮、挑戰、拍影片及控制器分析都在同一個網頁內操作。返回「場景控制」會接續原場景與手勢指令。工作區離開畫面時會暫停物理演算及聲音，錄影會收尾成可下載片段。重新整理前可先匯出實驗資料或影片。舊 `/lab.html` 書籤會開啟對應工作區。

手機直向控制艙在上方顯示即時情境，中段並列量測與同步平台，下方顯示兩軸輸入回饋。橫放手機後實景位於左側，可直接在實景上操作，右邊上下排列機構和輸入回饋。音效、暫停及急停在頂欄。「場景」可按分類或文字尋找應用，「儀表」可輕觸 A01–A06 檢查單腿，「工具」提供平台操作、雙視窗截圖與進階工作臺。點選「操控」、關閉按鈕或從面板標題向下拖動都能回到畫面。手機的返回鍵也能關閉控制艙面板。

機構內部以公尺、公斤、秒及弧度運算。姿態順序為 X、Y、Z、Roll、Pitch、Yaw。首頁以 mm 與度數顯示。校正高度為 480 mm，位移讀值須依儀表標示的基準判讀。

## 3 手勢與十三種應用

### 先試海浪，再挑戰光纖對位

1. 打開首頁，在自由操控的控制盤上向左拖動。放手後觀察平台維持指令，六腿長度各自改變。
2. 在圓盤上連點兩下回中。鍵盤焦點在圓盤上時可用方向鍵微調，Shift 加大步幅，Home 回中。
3. 拖曳 3D 場景從側面觀察接頭。使用滾輪或雙指縮放視角。在自由操控的圓盤上用雙指開合、旋轉，可以改變平台高度與偏航。
4. 點選「海浪補償」。先看底座動，再讀載台殘餘傾角。轉動羅盤改變來浪方向，向上拖動浪峰增大波幅。
5. 在完整場景庫選取「光纖耦合」。在晶片掃描面上橫掃、縱掃，留意相對耦合功率哪裡變高，再沿該方向縮小搜尋範圍。

首次進入時，平台以約 2.4 秒的小幅升降和轉動展示六腿協同。點按或操作鍵盤即可接手，啟用系統減少動態效果時直接進入自由操控。同一分頁的工作階段只播放一次。機構視窗下方的「自動置中」可在投球前先啟用。投球後，視窗下方會顯示球數、中心距離、速度及「清空球體」。清球只移除球體，保留當前平台和控制任務。

控制盤的 X 向右為正，Y 向上為正。自由操控的控制盤會保留放手位置，進階工作臺的迷宮搖桿則會回中。場景控制與實驗工作區各自保留模擬時間與球體。切回工作區後可接著操作。

自由操控提供三種軸對。傾斜模式分別控制 Roll 與 Pitch，範圍各 ±10°。平移模式控制 X 與 Y，各 ±70 mm。「升降與旋轉」將水平軸映射至 ±14° 偏航，垂直軸映射至相對原點 ±85 mm 的升降。組合指令仍需通過工作空間檢查。選擇「投球」後，在台面按下決定起點，拖曳可預覽初始拋物線，放開建立球體。點選一支致動器或行程列可檢視長度、速度、推力，也能在自由操控時微調單腿指令。

選「推台」後，在台面輕點可施加朝下的 0.65 N·s 衝量。拖曳再放開會增加沿台面的衝量，合成上限為 3.5 N·s。在同樣的拖曳方向下，試著分別推平台中心和外緣。偏心接觸帶來額外力矩，六腿伺服會產生不同的回復反應。開始拖曳的位置就是剛體受力點。

### 飛行、車輛、海事與地震

首頁十三張實景卡都可直接進入，網址也支援對應的情境識別碼。左窗呈現受控的飛機、載具或試體，右窗呈現縮尺平台。手勢放開後保留輸入，方便比對兩邊反應。輸入回饋會顯示兩軸指令。雙點實景、按歸零鍵或在實景聚焦時按 Home，都可將指令還原。台面姿態來自固定 240 Hz 步進的 Rapier 剛體，各場景的畫面和聲音共用模擬狀態。

1. **飛行座艙。** 客機飛越瑞士伯恩高地的山谷與湖面。在飛行畫面向右拖，觀察右機翼降低，再向下拖，看機鼻抬高。畫面下方並列機身坡度與實際台面橫滾。客機以 130 m/s 前進，使用協調轉彎關係「重力 × 坡度正切 ÷ 速度」更新航向。俯仰改變飛行高度，合成陣風在回中後繼續提供小幅姿態變化。客機外形、雙發動機與扇葉為原創模型，地表結合 swisstopo 正射影像及 Terrain Tiles 高程。[飛行情境素材](/worlds/flight/credits.txt)
2. **車輛動感。** 賽車沿 702.83 m 的閉合賽道前進。在賽道畫面左右拖動改變走線，上推加油、下拉煞車。試著在同一彎道用兩種速度通過，觀察台面側傾的變化。跟拍車身的道路、車輪與轉向都取用同一行進距離及航向。控制器由速度、道路曲率與橫向走線變化計算過彎線索，再由六腿重現可達範圍內的加速度體感。車體採用 vicent091036 製作的 Ferrari 458 Italia，並加上賽車塗裝與尾翼。[賽車情境素材](/worlds/driving/credits.txt)
3. **海浪補償。** 直接在海面拖曳向量端點可調浪向與浪幅。雙指旋轉調浪向，張開可加大波幅。觀察作業船的船舷、遠方海平線與浮標，再比較船身傾角和載台殘餘傾角。畫面與底座共享三組長湧浪的高度和斜率。船身隨合成波面升沉和傾斜，縮尺底座以 1:100 重現垂直位移。六腿以世界水平為目標，儀表保留實際追蹤誤差。海面細波、反射與泡沫用於顯示海況。[海事情境素材](/worlds/marine/credits.txt)
4. **地震振動台。** 在建築場景上從中立指令向上拖動加大震幅，讓震波先沿試體滑軌傳入。觀察地基的水平移動、屋頂的相對側移與回擺。再用雙指旋轉改變震向，觀察改為橫向激振後的試體讀值。地震輸入為十二秒循環的合成波，動態試體由 0.65 Hz 彈簧阻尼支承。地基取用台面實際位移，各樓層依試體的相對位移套用一階假設振形。樓層越接近屋頂，側移越大。地基運動和樓層側移皆以 90 倍長度比例繪製。儀表以原始台架毫米值顯示，九層立面的目的是讀出沿高度變化的運動，結構抗震設計需另作結構分析。[地震情境素材](/worlds/seismic/credits.txt)

桌面情境視窗的相機或手機「工具」內的「擷取雙視窗」會將兩個視窗和兩項同步量測合存為 PNG。按暫停可定格比對。按急停會中止情境命令並鎖住致動器的制動目標。解除制動後，首頁會從該情境起點重新開始。在首頁網址後加上 `?scene=` 和下表識別碼，可直接進入指定應用。

### 實景手勢、精密操控與聲音

點選卡片會在瀏覽器允許後啟用場景聲音。從直達網址進入，可操作實景、專屬儀器或點選喇叭。主導覽與情境視窗的喇叭共用開關，會記住主動設定的靜音偏好。暫停、急停及分頁進入背景會收起聲音。回到自由操控時仍可從六組致動器的馬達與碰撞聲聽出機構動態。

每個實景都能用單指連續拖曳，也支援滑鼠。按住 Shift 拖曳可用四分之一靈敏度微調。飛行、賽車與列車能雙指旋轉轉向或傾斜，同向上推或下拉則控制第二軸。海浪、地震、站姿擾動可雙指旋轉改方向、開合改強度。光學、對接與光纖可雙指一起移動來精調位置。影院、加工與掃頻可用雙指橫移控制第一軸、開合控制第二軸；攝影則用旋轉調防震增益、開合調手震頻率。

在輸入回饋旁展開「精密操控」可使用下表的專屬儀器。實景與儀器共用當前指令，切換操作方式時會接續原值。

| 識別碼 | 精密操控中的操作 | 聲音的來源或意義 |
|---|---|---|
| `flight` | 駕駛盤左右壓桿，拉近抬頭、推遠低頭 | 左右渦扇與風噪隨姿態和負荷變化 |
| `driving` | 轉動方向盤，以兩支分開的踏板加速或煞車 | 引擎諧波隨車速與檔位改變，輪胎隨側傾與煞車產生摩擦聲 |
| `marine` | 轉羅盤選浪向，拖動浪峰改變海況 | 浪峰泡沫、柴油機與浮標鐘依波相位變化 |
| `seismic` | 拉高震波幅度，向兩側撥震向指針 | 台面與試體運動驅動低頻地鳴和窗框震響 |
| `optics` | 橫擦兩支正交鼓輪，讓焦面光點靠近十字中心 | 天文台山風與副鏡微調馬達 |
| `docking` | 拖動光學捕獲環或點選瞄準位置，偏心小於 3 mm 時自動進給 | 艙內通風、接近提示及對準雙音 |
| `rail` | 以傾角調整器修正車體，再推拉主控桿改車速 | 走行馬達、輪緣音與按里程觸發的接縫聲 |
| `cinema` | 撥動膠片調片速，用推桿調座椅動感 | 按影片段落合成和聲、風聲與低頻節拍 |
| `camera` | 橫擦兩個鏡筒環，分別調防震增益與手震頻率 | 攝影棚通風及補償馬達 |
| `balance` | 從雙足圖向外劃出向量，以方向和長度設定擾動 | 測試開始、復位節拍，以及移動踏台聲 |
| `machining` | 轉手輪調進給，向外拖或雙指開合調刀路半徑 | 空轉主軸、進給伺服及風扇 |
| `vibration` | 沿頻譜掃過共振點，用阻尼調整器比較試體響應 | 每次激振峰值驅動機殼和試體共鳴 |
| `photonics` | 在晶片掃描面描路，依量到的功率顏色尋峰 | 功率轉為可聽音高與脈衝密度，協助對位 |

三維情境的素材來源可由情境視窗右下角開啟。聲場由 Web Audio 在本機即時計算，使用振盪器、濾波噪聲、聲像與短音包絡。光纖情境的音高代表光功率；地震、平衡與振動情境的聲音用於辨認擾動及節奏。加工以圓弧乾跑驗證輪廓；人體動作呈現支撐面擾動，量測量為台架位移。

### 其他應用儀表

放大右側機構視窗後可檢視對應的詳細量測儀表。地平儀將實際橫滾與俯仰畫成水平線，海事模式另以虛線標出底座。位置量測圖繪製相機像移、焦面、捕獲環、支撐面、刀尖或光纖的 X／Y 點位，單位依應用而定。對接與加工會再畫出允差或刀路的參考圓。響應波形則保留最近六個模擬秒的資料，可用來比較震動、共振與影院動作的時間變化。

機構量測來自剛體狀態。地震與掃頻的試體本身是 Rapier 動態剛體，附在台面 X 向滑軌上。載台驅動試體，彈簧阻尼的反作用也傳回載台。地震讀值取自關節的相對位移。掃頻用試體與載台的實際世界 X 位移計算均方根比值，使用 1.2 秒時間常數的指數平均。防震以一階光軸追蹤器估算像移，光纖使用放大的高斯光斑。對接使用幾何誤差與進給閘門，曲面加工採無切削的圓弧乾跑，平衡擾動量測支撐面運動。真實設備的流場、飛行器動力學、人體反應、光學繞射與接觸鎖扣需要另建模型與校正。

程式依據為 `lib/applications.ts` 與 `tests/applications.ts`。

## 4 遊樂場與工程臺的介面

### 頁首、狀態列與工作區

頂端主導覽的「遊樂場」和「工程臺」可以在同一個頁面切換。工程模式另有「控制器」與「實驗與紀錄」入口。右上角的問號開啟操作指南，齒輪開啟幾何與機械限制，E-STOP 可立即關閉控制並讓致動器進入制動保持。急停後按「解除制動」恢復控制資格，或使用重設歸零開始新實驗。

系統狀態列顯示 NOMINAL 等狀態、固定物理頻率、控制頻率、可用致動器數量、動態／運動學模式與畫面 FPS。240 Hz 是固定模擬步進頻率，120 Hz 是預設回授控制頻率，FPS 是瀏覽器繪圖速度，三者不可互換。效能較低時，模擬時間可能無法與真實時間等速前進。

桌面介面包含左側控制、中間 3D 視窗與右側觀察面板；工程模式下方另有訊號監視器。面板之間可拖曳調整大小，收合後可按中央視窗邊緣的還原按鈕開啟。手機將平台畫面與目前的面板固定在同一螢幕。「操控」、「量測」、「工具」可以直接切換，工程模式另有「示波」。工具和參數清單可在各自面板內捲動。選頂端「場景控制」可返回原場景。直向畫面使用橫幅平台視窗，寬直向畫面的控制與量測並列在平台下方。

### 滑桿與精確數值

`Precision` 元件同時提供滑桿、數字輸入及正負步進按鈕。拖動滑桿可連續調整；在數字欄輸入後按 Enter 或離開輸入框才送出。送出時會檢查有限數值並限制在該欄允許範圍。數值未送出前，平台仍使用上一次有效命令。姿態欄位限制與機構可達限制是兩層檢查：即使數值在滑桿範圍內，組合姿態仍可能因致動器行程、接頭角度或合成傾角而被拒絕；請閱讀底部訊息。

### 攝影機與 3D 輔助顯示

攝影機預設包括 ORBIT、FRONT、TOP、ISO，更多視角中有 SIDE、致動器特寫、跟球與展示鏡頭。一般情況可在 3D 畫面拖動視角、縮放；投球拖曳或自動導演期間會暫時接管攝影機操作。迷宮與挑戰選頁會切到俯視，方便控制球的 XY 位置。

3D 工具列可開關 X-Ray 透視、Exploded 分解、致動器受力箭頭、地面網格、工作空間示意與負載熱圖。分解檢視會暫停模擬並拉開視覺零件，畫面位置不代表剛體的真實位置；工作空間網格也只是示意包絡，可達性仍由運動學與限制判斷。平移／旋轉操縱器迴圈切換關閉、XYZ 平移與三軸旋轉。另有展示模式及儲存截圖；截圖是目前 3D 視窗影像，不是整頁操作面板。

## 5 投球、清空、回原點與重設

### 精確投球面板

在中央視窗下方按「設定」，會切至工程模式的「投球」頁籤。先點選俯檢視或輸入 X/Y，再設定高度、方位角、仰角與初速度。投球座標及角度以當前平台區域性座標為準，平台傾斜時，程式會將區域性起點與速度旋轉到世界座標。

| 參數 | UI 範圍／預設 | 意義 |
|---|---|---|
| X、Y | 數值欄以平台半徑的 ±95% 限制；預設 90、65 mm | 球釋放起點，XY 各自限制不代表點一定落在六角形內 |
| RELEASE HEIGHT | 40–600 mm；預設 120 mm | 相對平台釋放高度 |
| DIRECTION／方位角 | −180° 至 180°；預設 −145° | 0° 指向區域性 +X，90° 指向區域性 +Y |
| ELEVATION／仰角 | −80° 至 80°；預設 −15° | 正值向上，負值向下 |
| POWER／初速度 | 0–1.5 m/s；預設 0 | 「力量」用初速度表達，0 是自由落下 |
| 投放物體 | 乒乓球、鋼球、木塊、圓柱、重物 | 改變形狀、質量、慣量及碰撞效果 |

物件選項標示乒乓球直徑 40 mm／2.7 g、鋼球 260 g、木塊 120 g、圓柱 350 g、重物 10 kg；單場景最多保留 12 個投放物件。已掉出平台的物件仍佔場景容量，請用清空球體釋放名額。球體追蹤針對球類物件，木塊、圓柱和重物主要作為剛體沙盒或負載觀察。

「中心」會把起點設定到 XY 原點並改為自由落球；「邊緣落球」採用 `(130, −70) mm` 的落球起點；「拋向中心」保留使用者已選的 XY，將水平方向改為 `atan2(−Y, −X)`，若原本速度是 0 且起點非中心，則提供 0.3 m/s 初速度。啟用中心方向鎖定後，修改 XY 會重新計算方向；手動修改方位角可解除鎖定。起點正好位於中心時，沒有唯一的朝中心向量，程式設定方位 0、初速度 0。

面板顯示初速度向量 `[VX, VY, VZ]`。3D 虛線是目前姿態下的自由飛行預覽，碰撞之後的運動仍由物理引擎決定；它不能保證實際落球後一定停在預測點。

### 在 3D 畫面拋球

遊玩模式按「在 3D 畫面拋球」，接著直接在平台上按下選起點，沿想丟擲的方向拖動，放開完成投球。拖曳距離影響速度；畫面提示顯示目前區域性 XY 與初速度，金色圈提供預測落點。這個快速操作採 120 mm 釋放高度、水平投出，速度依拖曳距離計算並限制最高 0.85 m/s。需要精確高度與仰角時改用工程投球面板。

拖曳期間會停用視角旋轉，避免投球與旋轉鏡頭同時發生。可用「取消」離開。進行手動計分關卡或影片錄製時不能啟動 3D 拋球，以免破壞固定起點或導演鏡頭。必須在有效平台區域按下才會取得投球起點。

### 三種重整行為要分清楚

| 操作 | 移除球體／物件 | 平台姿態與時間 | 目前自動任務 | 典型用途 |
|---|---|---|---|---|
| 清空球體／清空 | 是 | 保留 | 保留，等待下一顆球 | 過多物件、想重新投球 |
| 回原點／H | 否 | 發出回原點姿態命令 | 依一般手動姿態切換規則處理 | 保留場景並把平台擺正 |
| 重設歸零／重設模擬 | 是 | 新物理世界，時間歸零、平台回 HOME | 關閉並清除當次狀態與故障 | 重來整個實驗 |
| 開始／重新開始關卡 | 是，另準備一顆指定球 | 恢復固定關卡條件 | 使用手動挑戰控制 | 公平的計分起點 |

清空不是恢復出廠設定，也不應解除急停或改變暫停、置中等狀態。關卡正在計分時，一般投球與清空操作會停用；請使用關卡的重新開始按鈕。

## 6 遊玩模式的五個頁籤

### 自由探索

「投放乒乓球」快速加入標準球；「在 3D 畫面拋球」提供直接拖曳；「自動置中」將目前追蹤球送往區域性原點；「圓周運動」讓平台傾斜，使球沿設定的圓周移動。球的位置沒有被直接改寫成路徑座標，因而能觀察到誤差、接入與失敗。

圓周半徑可調 20–180 mm、切向速度 10–180 mm/s，方向可選逆時針或順時針。幾何尺寸較小時，工程面板依有效範圍縮小可用半徑。小半徑高速情況會自動限速；面板顯示「實際設定速度」與週期，請勿把要求速度當作每一刻的真實球速。先投球後啟用、先啟用再投球都可以。清空後重新投球仍會由目前任務接手。

### 手繪路徑

可以使用 8 字、愛心、花瓣、圓形四個預設，也可以在俯視區以滑鼠或手指一筆畫出路線。首尾會自動接合；灰色虛線是剛輸入的筆跡，紫線是平滑後的實際參考路徑。筆跡限制在中心半徑 200 mm 區域，每次最多取 1,024 點，點距過近會略過；無效、過短或退化的路線會被拒絕並顯示原因。

「循跡速度」可調 20–160 mm/s，預設 80 mm/s；這是希望使用的上限，急彎會降低區域性目標速度。畫完不會自動丟球，按「啟用這條路徑」才會啟用控制，並可用同一按鈕停止。球會先接入鄰近路段，然後平順加速。修改路徑或速度會重新規劃接入；交叉圖形仍依路徑順序前進，並非看哪一段比較近就隨意跳段。

面板顯示路徑長度與約一圈時間，右側顯示設定速度、目前目標速度、實際球速與追蹤誤差。手繪路徑與工程模式的「姿態關鍵影格軌跡」是不同功能：前者規定球在平台上的 XY 路線，後者規定平台自己的六維姿態。

### 滾球迷宮

選好關卡後按「開始關卡並放球」。程式會清空目前場景、恢復固定物理條件、安裝牆面與地板，並在指定起點準備一顆球。這個明確命名的開始按鈕會放球，與一般自動置中按鈕不同。

| 關卡 | 特色 | 限時 | 基準時間 |
|---|---|---|---|
| 01／折返入門 | 兩道牆與四個必經光圈，學習折返及煞車 | 120 秒 | 45 秒 |
| 02／交錯閘門 | 三道交錯牆，六個必經光圈 | 150 秒 | 60 秒 |
| 03／空洞之間 | 真實挖空的兩個落球孔洞，沿外圍安全路線前進 | 120 秒 | 45 秒 |

以搖桿、方向鍵或 WASD 控制傾斜。放開搖桿只代表回到水平，球還有慣性；接近轉彎或終點前，往反方向傾斜才能減速。必須依順序透過光圈；完成所有中繼點後，在金色終點附近停穩才能過關。迷宮終點要求接觸地板、中心距離小於 27 mm、速度小於 45 mm/s，持續 0.6 秒。掉入孔洞、離開有效平台、超時或介入自動控制會結束本次遊戲。

迷宮將 Rapier 的 lengthUnit 設為 0.05，以對應小球與小孔的接觸容差，避免預測接觸把球懸掛在孔口；回到一般世界初始化時恢復原設定。孔洞透過刪除對應地板碰撞區實作，影像與物理共用同一份地板分割資料；球進洞是真實落下，不是單純碰到色塊就宣告失敗。

### 挑戰與成績

「置中衝刺」限時 60 秒，以手動操作把球送到原點；「精準停球」限時 75 秒，把球停到偏心 `(-100, 100) mm` 的目標；兩者都要求中心距離小於 15 mm、球速小於 25 mm/s，持續 0.8 秒。「海浪生存」在持續晃動的底座上手動撐過 30 秒，球需維持在半徑 180 mm 的安全圓內。

「節能控制」限時 45 秒。把球停進偏心光圈並穩住 1.2 秒。從球第一次接觸台面開始，右側即時累計六腿的機械功。小幅傾斜、提早減速可避免反覆修正。結束時可下載印有焦耳數的成績卡。

挑戰會統一幾何、控制設定、摩擦與重力等條件，避免不同試次因先前實驗參數而失去可比性。畫面提供倒數、光圈進度與停穩進度條。前往工程臺查看量測時，同一顆球與本輪計時會繼續運作。開啟自動控制、重設或失去球體會結束本次計分。計時使用模擬時間；暫停也暫停遊戲時間。

成功時顯示分數、金／銀／銅牌、經過時間與接觸次數，可「下載成績卡」產生 1200 × 800 PNG，或「複製挑戰連結」邀請朋友從同一關卡開始。挑戰連結含 `?maze=關卡id` 或 `?challenge=挑戰id`，只選擇相同關卡，不會替朋友自動開局，也不會上傳或證明分享者成績。最佳成績只儲存在目前裝置、目前網站來源的瀏覽器儲存空間，沒有雲端排行榜、帳號競賽或防作弊驗證。

### 拍影片

先開始想拍的循跡、圓周或手動遊戲，再切到「拍影片」設定錄影；單純切到此頁不會停止原玩法。比例有橫式 16:9（1280 × 720）及直式 9:16（720 × 1280），長度可選 15、30、60 秒。可選「自動導演」讓攝影機依序呈現全景、跟球、機構特寫，或關閉以使用目前視角。可選「開啟並錄入模擬音效」。

按「開始錄製目前畫面」之後，設定暫時鎖定，可提前按「停止錄製」。錄製到設定時間會自動結束；切到背景分頁也會結束並保留已錄片段。完成後右側有原生影片播放器、格式、尺寸、長度與下載連結。影片載入影格後會顯示「影片可播放」及實際解碼尺寸；不支援預覽的格式會提示下載後使用播放器開啟。請在重整或離開網頁前下載，最新片段暫存於頁面記憶體，新片段會取代上一段的預覽。

錄影是系統自己的 3D 畫面與資料字幕合成，包含名稱、目前任務、球速、誤差與模擬時間；直式另含小型誤差趨勢圖。這不是螢幕分享錄影，不會錄進其他程式、瀏覽器分頁、麥克風或攝影機。聲音取自合成音效的 Web Audio 輸出。瀏覽器決定可用編碼；程式依序嘗試 WebM VP8/Opus、WebM VP8、WebM，再嘗試 MP4，下載副檔名依實際 MIME type 決定，不保證每臺裝置都有 MP4。目標擷取率 30 fps、影片位元速率 4 Mbps，片長上限 60 秒，累計緩衝超過 48 MiB 會提前停止。

程式依據：`app/playground.tsx` 全部遊玩面板、`lib/play-session.ts`、`lib/mazes.ts`、`lib/score-card.ts`、`lib/film-recorder.ts:FilmRecorder`。

## 7 工程模式詳細操作

### 左側「姿態」

X／SURGE、Y／SWAY 為 ±65 mm；Z／HEAVE 為相對基準 −80 至 +100 mm；Roll、Pitch、Yaw 各自可輸入 ±12°。合成傾角仍受整機限制，不能把三個角度的範圍解讀為可同時使用的保證值。按「回到原點」發出 HOME 姿態命令。

運動曲線可選 S-Curve、Minimum Jerk、Trapezoid、Linear、Step。它們決定目標姿態如何由目前值走到新值，還須透過逆運動學、致動器速度／加速度／加加速度與物理模型限制。Step 是目標階躍，不表示動態剛體瞬移。3D 操縱器提供 XYZ 平移或三軸旋轉入口。

### 左側「致動器」

六個 ACTUATOR 欄位用 mm 指定各腿目標長度，允許範圍來自當前幾何設定的最短／最長致動器長度。調整單腿時，正運動學會求出相容的平台姿態；無解或違反限制的組合會拒絕。故障腿不能由該欄直接調整。這個頁面特別適合觀察並聯機構中「一根腿的變化會同時影響多個自由度」。

### 左側「自動」

TASK CONTROL 有 AUTO LEVEL（自動水平）、CENTER BALL（閉迴路置中）、SEA COMP.（海浪補償）、TRAJECTORY（六維路徑）及 CIRCLE BALL（球體圓周追蹤）。每個按鈕都有對應 Active State，底下文字也會顯示啟用中的任務；再按同一任務可停止。SEA COMP. 與 TRAJECTORY 是保留現有物件的任務切換，與「實驗場景」中的重新開場不同。

其下有圓周半徑、切向速度與方向設定；VECTOR CONTROL 的 X±、Y±、Z± 每次沿世界座標改變 10 mm。DISTURBANCE 提供 1.2 N·s 線衝量、角衝量及連續擾動開關。CONTROLLER 可選 PID、Cascaded PID、LQR、MPC、Adaptive，再進入「控制參數與比較」作細部設定。

### 右側「總覽」

沒有可追蹤球或處於狀態重播時，總覽顯示平台實際 XYZ 與姿態。有球時顯示追蹤誤差、雷達軌跡、區域性 X/Y、VX/VY、球速及平台上／飛行中／已掉落數量。追蹤模式包括最新球、指定球及球群中心；掉落球會排除，連續投第二顆球不應使回授失效。指定球模式可選有效 BALL 編號。

圓周與路徑追蹤的控制目標是單顆球。球群中心模式使用各球位置的算術平均與分散半徑。所有球都受到同一片平台的傾斜與彼此碰撞影響。LOCKED／穩定表示符合該任務的誤差及速度門檻。

下方的六腿表格列出長度與負載，按一列可進入該腿檢視器。Jacobian condition number 反映目前姿態附近的運動學條件，接近奇異位置時可能變差；它不是所有物理安全性的綜合分數。

### 右側「物理」

物理模式可切動態或運動學。動態模式以六支軸向伺服器施力推動平台，球體與負載會反作用於平台。運動學模式以致動器動態與正運動學決定平台姿態，球仍使用剛體碰撞，但接觸不會反推平台，負載力為估算。切換模式屬世界重建操作，應先儲存需要的紀錄。

表面選項對應摩擦係數：橡膠 0.7、鋁 0.38、碳纖維 0.22、玻璃 0.08、冰 0.01。RESTITUTION 可調 0–1；數值較大通常更容易彈跳，仍受接觸條件影響。剛體沙盒可選物件型別並隨機加入，或只清空物件。PAYLOAD 為 0–300 kg，PAYLOAD OFFSET X 為 ±150 mm；後者用於負載偏心實驗。診斷顯示固定時間步、剛體數、求解迭代、伺服作功及球自轉。

### 右側「檢視器」

選擇 A1–A6，檢視實際長度、目標、誤差、速度、加速度、軸向力、電流估計、機械功率、溫度估計及累積行程。「致動器失效注入」將該腿驅動力設為零，可能導致失穩；關閉可恢復，整體重設會清除故障。

SENSOR SIMULATION 包含位置雜訊 0–8 mm、延遲 0–300 ms、掉包率 0–80%。它們用來觀察感測品質對閉迴路控制的影響；畫面可顯示模擬真值，但控制器接收的是經感測條件處理後的資料。電流與溫度以簡化模型估計，不是可直接拿來挑選實體馬達與熱設計的驗證值。

### 下方訊號監視器

通道可選 Pitch、Roll、Yaw、Heave、Ball X/Y、球速、選定致動器受力及 A1–A6 長度。圖例可開關目標與誤差；不同通道不一定都有對應目標線。圖表是近期樣本的監視窗，不是無限期資料庫。

時間列提供播放／暫停、單步 1/240 秒、重設、模擬時間、0.1／0.25／0.5／1／2／4 倍速度、狀態 RECORD、REPLAY、實驗 JSON 下載與指令控制檯。倍速改變模擬相對牆鐘時間的推進，不改變每一步物理 DT。

## 8 控制器、幾何與實驗工作臺

### 控制器視窗

控制器種類為 PID、Cascaded PID、LQR、MPC、Adaptive。PID 型別的 Kp 可調 0–3、Ki 0–0.5、Kd 0–2；MPC 的預測步數可調 10–60 steps；LQR 顯示求出的 K position／K velocity。SERVO DAMPING 可調 0.6–1.8。右側顯示穩定時間、RMS 誤差、最大誤差、最大傾角、伺服作功與控制頻率。

「比較 PID／LQR／MPC」會建立獨立測試模擬，以相同起始位置 `(100, −65) mm`、初速度 `(0.025, 0.015) m/s` 分別執行 14 秒，逐列呈現結果。比較不會把主畫面當作測試世界，也不代表所有狀況的排行榜；結果受目前幾何、模式、表面與設定影響。預設穩定判定為誤差 <4 mm、速度 <15 mm/s 連續 0.75 秒。

### 幾何與機械限制

可編輯底座接點半徑 0.30–0.55 m、上平台接點半徑 0.20–0.38 m、最短腿長 0.25–0.50 m、最長腿長 0.50–0.85 m、平台質量 5–80 kg、負載 0–300 kg、腿最大速度 0.03–0.30 m/s、最大加速度 0.2–3 m/s²、最大加加速度 2–40 m/s³、每腿最大軸向力 200–5000 N。參數必須相容，按「套用幾何並重新校正」才提交；提交會更新模型並重設至原點。

### 實驗的「場景」

內建 Basic Motion 六自由度迴圈、Actuator Dance 致動器協同、Ball Drop 自由落體與彈跳、Ball Recovery 邊緣落球與救援、Disturbance Rejection 擾動抑制、Sea Stabilization 船體運動補償、Precision Tracking 六維軌跡、Workspace Sweep 條件數探索、Actuator Failure 單腿失效、Emergency Stop 制動示範。選場景會初始化該實驗所需狀態，與自動頁「保留物體」的任務切換不同，操作前先匯出要保留的結果。

### 實驗的「軌跡」

先回主畫面調平台目標姿態，再按「儲存目前姿態」建立關鍵影格。第一格從 0 秒開始，後續每格預設增加 2 秒；至少兩格才能播放。表格顯示各格時間、XYZ、RPY，可移除影格。播放時以平滑插值產生平台姿態，仍經致動器限制執行。這是六維平台姿態時間軸，並不指定球的空間路徑。

### 實驗的「頻率響應」

「執行 0.1–2 Hz 掃頻」依序測試 0.1、0.2、0.4、0.7、1、1.5、2 Hz，施加 Pitch 2° 正弦命令，以末段基頻振幅與相位估計增益 dB／相位度數。每個測點用獨立模擬世界；低頻需要較長模擬時間。飽和、非線性碰撞或失穩會讓結果不適合直接當作線性傳遞函式。

### 指令控制檯與指令腳本

控制檯每次執行一行，指令碼頁每行一個命令，最多執行前 100 行；`wait` 以毫秒等待，單行限制 0–10,000 ms，可隨時按停止。停止指令碼只終止後續命令，已送出的姿態或任務不會自動撤銷。

```text
pose pitch 5deg
wait 1500
pose x 10mm
wait 1000
home
wait 1500
ball.spawn
center on
```

支援 `pose x/y/z/roll/pitch/yaw 數值`、`actuator 3 length 490mm`、`home`、`ball.spawn`、`center on`、`center off`、`controller pid/lqr/mpc`、`disturbance`、`estop`、`reset`。pose 的平移數字按 mm、旋轉數字按度解讀，Z 仍是相對 480 mm 基準的偏移；建議總是加上正確的 `mm`／`deg` 以方便閱讀。`wait` 是指令碼執行器指令，不能在單行工程控制檯當作模擬器命令。指令碼可下載 TXT。

## 9 三種紀錄與儲存方式

### 狀態錄製／重播

工程時間列的 RECORD 或實驗「錄製與儲存」中的「開始新錄製」，以每秒 30 組儲存平台姿態、目標、底座姿態、六腿資料及物件位置／四元數。開始新錄製會清除上一份狀態錄影，上限 9,000 格，約五分鐘。REPLAY 播放記錄的狀態而不重新進行同一段物理求解；播放到底會暫停。要返回正常互動，請重設模擬。

這類紀錄適合重看運動過程與匯入實驗，不是 MP4/WebM 影片，也沒有音軌。它不儲存 Rapier 接觸求解器、所有動量或整個世界的完整快照，因此不能承諾從任意一格無縫續算並重現完全相同的碰撞結果。

### 實驗 JSON 與本機預設

「匯出實驗 JSON」下載 `StewartLab-experiment.json`，目前資料格式標記 `format: "StewartLab"`、`version: 1`。內容有幾何、控制、物理、運動曲線、場景名稱、圓周參數、手繪路徑、初始狀態快照、姿態關鍵影格、結果摘要、已錄狀態與近期訊號樣本。資料格式版本 1 不表示產品仍是 1.0。

「載入實驗 JSON」接受不超過 128 MiB 的檔案，檢查格式、數值與陣列長度，套用有效參數並建立新模擬。可載回 60、120、240 Hz 的控制迴路設定、配重偏心距與支援的載具。紀錄最多讀入 9,000 格，軌跡最多 30 格。載入會恢復可重播資料與目標設定。要完整留存挑戰成績或已編碼影片，請另下載成績卡或影片。

「儲存本機預設」把參數存入 `localStorage` 的 `stewart-lab-preset`，刻意移除 `recording` 與 `samples`，避免長紀錄佔空間；「還原本機預設」重新載入。瀏覽器若禁用本機儲存，介面會提示，仍可用 JSON 檔案儲存。

### 訊號 CSV

「訊號 CSV」輸出欄位 `t,pitch_target_deg,pitch_actual_deg,ball_x_mm,ball_y_mm,energy_J`，可用試算表分析。歷史陣列最多保留 900 筆近期樣本；因此 CSV 不是從網頁開啟起無限累積的全程資料。若需要長時間分析，維護時應明確擴充資料蒐集與匯出策略，並同步更新記憶體上限與本檔案。

程式依據：`lib/simulation.ts:startRecord/replay/snapshot/exportExperiment/loadExperiment/command`、`app/dialogs.tsx:LabDialogs`。

## 10 音效、影像與資料的正確解讀

致動器聲音由 Web Audio 即時合成，六支聲源依各腿速度、加速度與負載調整音高／音量，並依位置作立體聲聲像。接觸聲由物理接觸力事件觸發，包含材料差異與短時包絡；不是實體致動器或球碰撞的實測錄音。開始前需使用者點選音效開關，符合瀏覽器音訊啟動機制；音量可調 0–100%，每格 5%。暫停、急停與靜止情況會抑制致動器噪聲。錄影片勾選音效會開啟同一個音效系統並錄入它。

遊玩模式的青綠箭頭表示速度、琥珀箭頭表示量測得到的淨加速度、紫色箭頭表示指向目標的方向。箭頭長度經視覺化縮放和上限處理，並非以畫面尺寸直接讀出 N 的力計。加速度包括接觸、重力投影、阻尼與平台運動等共同結果，不能把橘色箭頭單獨命名為重力。球上的接縫與色點協助觀察自轉方向，位置與姿態由物理狀態更新。

機構由具質量的套筒、活塞、載台與接頭約束構成。底座模型設有安裝開口、隔振腳、銷座、螺栓與帶散熱片的驅動器。每條腿顯示鉻質推桿、拉桿、馬達與齒輪箱外殼、回授接頭和桿端軸承。橘色電纜隨兩端位置變形。Three.js 使用物理材質、環境反射及陰影貼圖，將同一總成及同一材質的部件合批繪製。

固定五金與標示跟隨所屬零件，線束曲線為視覺近似。螺紋接觸、線束內力、油液流動與裝配公差屬未建模項目。場景庫的十三張即時實景截圖用於選擇應用。3D 台座和應用載具則由瀏覽器即時繪製。載具附在載台剛體上，依外形拆為多個凸碰撞體，球可碰撞座椅、架台或對接環，並透過台座傳回作用力。載具的質量與慣量另計，工程面板仍可加入額外偏心配重。

## 12 啟動、開發與建置

### 本機一鍵啟動

本機需有 Node.js 22.13 或更新版本，或可由啟動器定位的 Codex 桌面版內建執行環境。於已建置的專案資料夾中雙擊「啟動 HEXAMOTION.cmd」，會重用或啟動本機服務，並開啟 `http://127.0.0.1:4187/`。`/?panel=free` 和 `/?panel=engineering` 對應遊樂場與工程臺，`/?reference=manual` 開啟站內手冊。結束使用後可雙擊「停止 HEXAMOTION.cmd」。兩支啟停檔需與 `scripts`、`dist` 放在同一專案根目錄。

本機服務綁定回送位址。健康檢查路徑為 `/__stewart_health`，應用識別是 `hexamotion-studio`。埠號被其他程式使用時，啟動器會返回錯誤。伺服器日誌在 `work/launcher-v2/`。若要在另一個埠自行執行靜態服務，可以設定 `HEXAMOTION_PORT` 後執行 `pnpm start`。

### 從原始碼啟動

在專案根目錄開啟終端機，執行下列指令。Vite 預設開發埠為 4186，網址以終端機實際印出的為準。

```powershell
pnpm install --frozen-lockfile
pnpm dev
```

正式打包及測試採下列流程。建置輸出在 `dist/`，包含首頁、完整工作臺與各自的資源。修改原始碼後，需要重建才能由本機正式服務取得新版。

```powershell
pnpm exec tsc --noEmit
pnpm test
pnpm docs:check
pnpm build
```

## 13 資料儲存與隱私邊界

目前 app／lib 應用程式碼沒有把球體運動、模擬資料、影片或本機成績自動送往雲端的業務 API。物理世界、控制器及影片合成都在當前瀏覽器執行。網站託管服務仍負責傳送 HTML／JS／WASM 等資源，瀏覽器與託管平台各自的基本網路請求不能解讀為應用完全沒有網路活動。

頁面重新整理後，未下載的影片、未匯出的狀態紀錄與當前剛體世界會消失。只有使用者儲存的本機預設、工作臺最佳成績留在 localStorage；下載的 JSON／CSV／PNG／WebM／MP4 留在使用者選擇的下載位置。瀏覽器來源包含協定、網域與連線埠，所以線上版、localhost:4187、localhost:4186 是不同的儲存區，成績不會自動同步。清除網站資料、無痕模式結束、換瀏覽器或換裝置，都可能失去本機儲存資料。

成績卡由 Canvas 產生；影片使用專屬 Canvas 串流及合成音訊，不請求麥克風與攝影機許可權。按複製挑戰連結才會寫入剪貼簿，失敗時顯示可自行複製的連結。需要長期保留資料，應下載檔案並自行備份。

## 16 座標系、尺寸與預設參數

### 座標與姿態慣例

內部統一使用 SI 單位：公尺 m、秒 s、公斤 kg、弧度 rad、牛頓 N。畫面上的位移通常換算為 mm，角度換算為度；球速在不同儀表依標籤顯示為 m/s 或 mm/s。世界座標 Z 向上，重力預設沿負 Z 軸。平台姿態為六元素陣列 `Pose = [x, y, z, roll, pitch, yaw]`。旋轉採 Three.js 的 ZYX Euler 次序，可表示為 `R = Rz(yaw) Ry(pitch) Rx(roll)`，再轉為四元數供剛體與畫面使用。

校正原點 `HOME = [0, 0, 0.48, 0, 0, 0]`，即平台座標原點距世界 Z=0 平面 480 mm。控制檯的 Z 位移讀值以 480 mm 為基準；例如 `pose z 20mm` 的絕對 Z 目標為 500 mm。球的位置、投球起點、圓周與手繪路徑 XY 均以「隨上平台移動的區域性座標」表示，因此旋轉平台後，球的區域性 XY 不等同其世界 XY。

程式依據：`lib/kinematics.ts` 的 `Pose`、`HOME`、`quaternion()`、`poseFromTransform()`；`lib/simulation.ts` 的 `measure()`、`command()`。

## 17 運動學：從姿態到六腿長度，再由長度求回姿態

### 逆運動學 IK

給定上平台平移向量 t、旋轉矩陣 R、上接點 pᵢ，以及底座平移 tᵦ、旋轉 Rᵦ、底接點 bᵢ，第 i 支腿的端點為 `Pᵢ = R pᵢ + t` 與 `Bᵢ = Rᵦ bᵢ + tᵦ`；腿長直接計算 `Lᵢ = ‖Pᵢ − Bᵢ‖`。IK 因此是幾何距離運算，不需迭代。底座姿態獨立存在，使海浪模式可以移動底座，而上平台仍追蹤世界座標中的水平目標。

### 正運動學 FK

FK 已知六個腿長，從目前平台姿態作為初始猜測反求六維姿態。每次迭代先做 IK 得到長度殘差，再以每維 `1e-6` 的有限差分建立數值 Jacobian，解出姿態修正量。線性系統採含最大絕對值主元選擇的 Gauss–Jordan 消去法；主元小於 `1e-12` 視為無法可靠求解。

FK 最多進行 14 次迭代，每步平移修正限制為 ±35 mm、旋轉修正限制為 ±0.1 rad，並依序嘗試 1、0.5、0.25、0.125 的縮放係數，僅接受能減小殘差平方和的步伐。若最大腿長殘差低於 `1e-7 m` 可提前返回；最後一般有效門檻為 `1e-5 m`，同時要求數值有限且 Z>0.18 m。這是依初始姿態尋找附近解，不是列舉所有 Stewart 機構組裝分支的全域求解器。

單腿長度調整先改變指定腿目標，再經 FK 與機械限制驗證；無解或超限時拒絕命令。Realtime 模式也以 FK 把六支伺服命令長度轉成平台運動。

### Jacobian、條件數與力分配

實體 twist Jacobian 的第 i 列為 `[uᵢᵀ, (rᵢ × uᵢ)ᵀ]`，其中 uᵢ 是從底接點指向上接點的單位向量，rᵢ 是上接點相對平台原點的位置。它把平台的世界線速度與角速度對應到腿長變化率。FK 使用的有限差分 Jacobian 則對 Euler 姿態變數求導，兩者用途與旋轉座標意義不同。

監測條件數時，旋轉三欄除以上接點半徑進行尺度正規化，再計算無限範數形式 `κ∞(J)=‖J‖∞‖J⁻¹‖∞`。求逆失敗時回傳大值 `1e9`。狀態顯示的 `SINGULARITY` 門檻是條件數大於 100；它是數值接近奇異的指標，不是結構強度保證。

力分配採虛功關係 `Jᵀ f = wrench`。Full Dynamics 使用載台與配重的質量及世界質心計算重力前饋，另外考慮各腿套筒及活塞的自重投影。偏心配重以邊長 100 mm 的立方體慣量加入載台質量性質，在側移質心時會改變真實受力分配。工作空間網格為示意，可達性由 `limits()` 的實際幾何判定。

程式依據：`lib/kinematics.ts` 的 `endpoints()`、`ik()`、`solve()`、`fk()`、`jacobian()`、`condition()`；`lib/simulation.ts` 的 `setActuator()`、`tick()`。

## 18 物理、伺服與平台運動

### Full Dynamics 關節動力學

空載世界含 15 個剛體。固定地板與可動底座之外，有 24 kg 的動態載台、六個 1.30 kg 套筒和六個 0.48 kg 活塞。每支腿包含可雙向傾擺的防轉下座、具行程止擋的滑動接頭與上球接頭，總計 18 個 Rapier 脈衝關節。預設套筒由 265 mm 主缸與 80 mm 導套組成，活塞桿長 360 mm。主缸、導套、桿的碰撞半徑分別為 30、19.5、13 mm。達到 680 mm 最大長度時，仍保留 25 mm 的伸縮搭接。自訂行程依最大長度等比例改變零件長度，並檢查收納餘隙。相連關節的近鄰零件略過彼此碰撞。底座碰撞網格保留中心孔、六個槽口及六個支腳。

伺服推力以量測端點距離及相對速度閉迴路計算。F 為 20,000 N/m 乘長度誤差，加上 566 N·s/m 乘速度誤差及重力前饋，最後限幅至正負 1,800 N。速度項採兩端剛體的線速度與旋轉端點速度在腿軸上的分量。套筒與活塞受到大小相同、方向相反的軸力，透過上球接頭與防轉下座將反力傳給載台與底座。下座約束缸軸方向的扭轉，活塞桿沿滑軌進出，上端固定銷隨載台支架運動。投入球體會影響載台受力，關節的數值容差與伺服柔順性亦會留下可量測的偏差。

滑動關節執行 380 至 680 mm 的實體行程限制。每步 1/240 s，以 12 次求解迭代處理關節與接觸。角度上限由命令幾何檢查及球座柔性止擋共同處理。超限回復剛性為 220 N·m/rad，角阻尼為 4 N·m·s/rad，力矩上限為 90 N·m。極端衝擊可讓約束留下短暫的數值偏差。

載具的縮尺模型質量以 kg 計算。飛行 3.2、車輛 3.8、海事 2.6、地震 2.4、望遠鏡 1.6、對接 3.6、鐵路 3.4、影院 2.8、相機 1.4、平衡 2.0、加工 5.2、掃頻 2.2、光纖 1.5。切換情境會替換載具碰撞體並重算載台質量性質。

振動台各有 0.8 kg 的固定總成。地震試體可動質量為 1.6 kg，固有頻率 0.65 Hz，阻尼比 0.09。掃頻試體為 1.4 kg，固有頻率 1.02 Hz，阻尼比可在 0.04 至 0.20 之間調整。兩者都使用沿載台 X 軸的 Rapier 滑動接頭與 ±40 mm 止擋。彈簧剛度為 m(2πf)²，阻尼係數為 2ζm(2πf)，作用力限幅至 100 N。地震台改變的是震向，量測向固定在滑軌軸線。此單自由度試體可重現方向性、共振與衰減。

### Realtime 模式

上平台改為 kinematic position-based 剛體。六腿命令先經伺服命令動態與 FK，得到下一個平台位置和旋轉，球體仍有剛體碰撞、重力與滾動。接觸不會反推此模式的平台；儀表中的負載力由 Jacobian 與平台加速度近似估算。施加外部衝量時改以小幅目標位移與傾角近似擾動，因此兩模式的力學結果不可視為相同。

### 命令速度、加速度與 jerk 限制

IK 的理想腿長不會直接送到物理伺服。每腿命令使用二階追蹤形式，自然頻率 `ωn=18/√(1+0.25·payload/mass)`，阻尼比預設 1.05。希望加速度為 `ωn²·位置誤差−2ζωn·命令速度`，再依可用速度餘裕限制加速度。`accelerationCap()` 用 24 次二分搜尋，估計在最大 jerk 下讓加速度逐步回到零所需的速度餘裕。之後每一步的加速度變化限制為 `maxJerk·DT`，累積為命令速度與命令長度。

這些上限管理的是伺服命令；Dynamic 實際腿長、速度與加速度由受力、碰撞和平台運動量測而來。強烈衝擊或失穩時，實際值可能超出命令設定，不能把設定上限誤讀成剛性物理擋塊。

### 五種點到點輪廓

姿態移動使用 `p(u)=p₀+(p₁−p₀)s(u)`，u 是移動時間除以規劃時間並限制在 0～1。未指定時間時，時間至少 0.55 s，或取最大腿長命令距離／最大速度的 1.8 倍。

| 輪廓 | s(u) | 性質 |
|---|---|---|
| Linear | u | 線性插值 |
| Step | 1 | 立即切換規劃目標，後段伺服限制仍生效 |
| S-Curve | 3u²−2u³ | 起迄速度為零的三次 smoothstep |
| Minimum Jerk | 10u³−15u⁴+6u⁵ | 起迄速度、加速度均為零 |
| Trapezoid | 前後四分之一為二次、中段線性 | 對稱加減速區與等速區 |

介面的 S-Curve 名稱指上述三次曲線，並非工業控制器常見的完整七段 jerk-limited 時間最優規劃。系統另在致動器命令層施加 jerk 上限。使用者儲存的六維關鍵影格每次自動增加 2 s，相鄰影格用三次 smoothstep 插值並迴圈播放；最後一幀回到第一幀時不會自動建立額外閉合段，製作迴圈動畫時宜自行讓首尾姿態一致。

| 物件 | 模型尺寸 | 質量 |

| 乒乓球 | 半徑 20 mm | 2.7 g |
| 鋼球 | 半徑 20 mm | 260 g |

## 19 球體定位、多球策略與閉迴路控制

### 從物理世界取得球體狀態

控制追蹤乒乓球及鋼球。先以平台四元數的反旋轉把球世界座標轉成平台局部座標。球的相對速度會扣掉載台在該世界點的速度，含載台質心線速度與繞真實質心的角速度分量，再投影回平台座標。偏心配重與載具改變質心時，量測仍使用即時剛體狀態。

球的區域性 Z 低於 -35 mm，或 XY 半徑大於 `topRadius+55 mm`，判為 lost。未 lost 且 Z>95 mm 判為 airborne，暫不納入有效控制集合。`contact` 以球中心高度接近 42 mm、容許誤差 ±14 mm 判斷；這是幾何近似，不是逐步查詢接觸流形。遊戲另以球中心 Z<5 mm 提早判定掉入孔洞失敗。

### 多球目標選擇

「追蹤最新球」選擇目前有效集合中最後加入的球；「指定球體」優先採指定 ID，指定球不可用時回退至最新有效球；「球群中心」使用所有有效球的算術平均位置與速度。球群中心未以質量加權，因此混合乒乓球與鋼球時，不等於物理質心。尚在空中的新球不會立即奪走已接觸球的控制目標。

有效目標 ID 組合改變時，系統清除積分、預測歷史、延遲佇列、穩定判定和循跡接入狀態，重新接管新目標。這是第二顆球加入後仍能正常工作的關鍵。掉落球持續存在於場景中，但不再送入閉迴路；失去所有球時控制功能保持啟用，等待下一次投放。圓周／手繪路徑限單球追蹤，若原本為球群模式會切至最新球；一片平台只能提供共同的傾斜輸入，不能讓每顆球獨立追蹤不同位置。

### 五種球控制器

預設 PID 設定為 Kp=0.4、Ki=0、Kd=0.4。每個 XY 軸各自控制，輸入為相對參考點的位置誤差 e 與速度誤差 v，輸出為傾角；X 軸輸出對應 Pitch，Y 軸輸出反號對應 Roll。

1. PID：`u=−Kp·e−Kd·v−Ki·∫e dt`。積分限制在 ±0.3，且未飽和時才接受新積分值，提供簡化 anti-windup。
2. Cascaded PID：外迴路先給 `vtarget=clip(−2Kp·e, ±0.25 m/s)`，內迴路計算 `u=Kd·(vtarget−v)−Ki·∫e dt`。這是位置－速度串級結構，沒有額外實作第二組可獨立調整的完整 PID 參數。
3. LQR：對薄殼球的線性化滾動雙積分模型解離散代數 Riccati 方程。狀態為 `[位置,速度]`，`A=[[1,dt],[0,1]]`，`B=[0.5·0.6g·dt²,0.6g·dt]`，Q 對角為 `[1,0.7]`、R=3。最多迭代 1,500 次，矩陣變化小於 `1e-9` 提前停止。增益建立時固定 dt=1/120、g=9.81。
4. MPC：每軸使用 box-constrained 有限預測時域控制，步長固定 0.035 s、步數 10～60，預設 30 步約預測 1.05 s。動態同樣是 0.6g 的雙積分；以先前解向前移一步 warm start，做 45 次倒傳伴隨梯度更新，每次以 0.00045 步長投影回傾角上下限。終端位置／速度代價權重 9、4，階段位置／速度權重 1.2、0.8，控制量權重 3。它限制的是傾角，沒有加入牆壁、球間避障或完整六維機構動態的最適化約束。
5. Adaptive：沿用 PID，只讓 Kp 乘上 0.75～1.3 的倍率；誤差大於 20 mm 時倍率以每秒 0.015 增長，否則以每秒 0.005 減少。這是啟發式增益調整，未進行系統辨識或模型參數學習。

LQR/MPC 的內部重力與離散時間固定，因此修改物理重力或控制頻率時，不會自動重算完整模型。圓周／手繪路徑的加速度前饋則使用當前重力值；實驗比較時應留意這個差異。

### 感測器模擬

球位置感測以 240 Hz 的物理時鐘取樣。每個成功取得的樣本記錄模擬時間、球的狀態與平面位置，歷史佇列最多保留 120 筆。X、Y 分別加入均勻分布的噪聲與固定偏差，單位為 mm。速度沿用量測值。dropout 決定每次取樣是否遺失。控制器按自己的更新頻率讀取時間戳早於傳遞期限的最新樣本，並在收到新的有效樣本時更新回授。傳遞期限為當前模擬時間減去設定延遲。噪聲、偏差、遺失機率和延遲預設為零。亂數種子初值為 137，遊戲重新開始時會重設種子。

### 回復能力與穩定指標

儀表以距平台外緣的餘裕減去估計煞停距離 `v²/(2·0.6g·sin(tiltLimit))` 判斷 RECOVERABLE／MARGINAL／UNRECOVERABLE；餘裕小於零為不可回復估計，小於 50 mm 為邊際狀態。這是保守程度有限的單維近似，沒有考慮伺服延遲、球間碰撞與完整六角邊界，不能保證一定救回球。

置中完成須平均中心誤差小於 4 mm、每顆受控球接觸且速度低於 18 mm/s，並連續維持超過 0.75 s。單球 RMS 半徑需小於 4 mm；多球允許群聚半徑 `22√N mm`，避免把兩顆分散但平均恰好為零的球誤判為完成。圓周／路徑則累積追蹤誤差 RMS，不使用「停穩置中」判定。RMS 與峰值會在目標組合改變或啟用新控制時重算。

程式依據：`lib/simulation.ts` 的 `measure()`、`controlStep()`、`setAuto()`；`lib/controllers.ts` 的 `BallController`、`lqrGain()`、`PredictiveController.predict()`。

## 20 圓周與手繪循跡演算法

### 圓周

預設半徑 80 mm、切向速度 80 mm/s，可選正／反方向；半徑設定範圍 20～180 mm，並依平台內切圓再扣除 45 mm 的安全距離限制最大值。速度設定 10～180 mm/s，但實際速度採 `min(要求速度,1.2r,√(0.35r))`，分別限制要求值、角速度約 1.2 rad/s 與向心加速度約 0.35 m/s²。因此小圓會自動降速，介面設定速度不一定等於穩態採用速度。

控制啟用本身不投球。球接觸後，以目前 XY 的 atan2 決定接入相位；前 3 s 用 minimum-jerk 曲線移到同相位的圓周點，接著 3 s 將角速度以 `3u²−2u³` 平滑拉高，最後等角速度繞行。參考位置、速度、切向／向心加速度皆解析計算。控制器處理位置和速度誤差，再加入 `pitchFF=ax/(0.6g)`、`rollFF=−ay/(0.6g)`；合成 Roll/Pitch 限至 8°或更小的機械限制。參數更動或受控球改變時重啟平滑接入，演算法沒有把球的位置直接設定到圓上。

### 手繪路徑前處理

預設提供 8 字、愛心、三瓣花與圓形，每種先產生 180 個點。自由繪圖與預設點都走相同編譯流程：

1. 接受 4～2,048 個有限 XY 點，先把點投影限制於安全半徑內，移除相鄰間距小於約 0.1 mm 的重複點。
2. 路徑自動首尾閉合；閉合總長須至少 80 mm，寬度與高度各至少 15 mm，排除單點或純直線折返。
3. 沿折線弧長均勻重取樣成 48 個控制點，再做三輪 `(前點+2×本點+後點)/4` 平滑。
4. 建立週期三次 B-spline，計算位置、一階導數與二階導數，再求單位切向量 T、曲率向量 K；用 1,536 個取樣點建立速度與時間查表。

因此實際控制的是畫面中平滑後的閉合曲線，不會逐點硬追使用者原始尖角。原始路徑會保留供再次編譯；過於短小、尖銳或複雜的路線會拒絕，並顯示原因。

### 急彎減速與沿線運動

要求速度限制為 20～160 mm/s。每個取樣點先採 `v=min(vrequest,√(0.25/κ),1/κ)`，限制向心加速度與曲率造成的方向變化率。最低採用速度若低於 2 mm/s 即拒絕路線；四輪正向／反向傳播以 `vnext²≤v²+2a·Δs` 限制切向加速度，a=0.08 m/s²。每段時間用平均速度積分，總週期超過 300 s 或非有限值則拒絕。

球第一次接觸時先找 1,536 個點中距球最近的相位，前 3 s minimum-jerk 接入，再以 3 s 時間縮放平滑加速。參考速度為 `T·v`，加速度為 `K·v²+T·a`，送入與圓周相同的誤差控制加前饋。弧段查詢以二分搜尋時間表，並以該段常加速度近似換算弧長。這個速度規劃處理曲率、切向加速度及安全範圍，沒有計算全六腿最適時間或自動障礙物避障。

程式依據：`lib/circle-path.ts` 的 `circlePath()`；`lib/drawn-path.ts` 的 `presetPath()`、`compilePath()`、`followPath()`；`lib/simulation.ts` 的 `configureCircle()`、`circleEffectiveSpeed`、`configurePath()`、`controlStep()`。

## 21 投球與擾動輸入

精準投球以區域性起點 XY、距平台表面高度、方位角、仰角及初速度描述。方位角 a、仰角 e、速度 s 對應區域性向量 `[s cos(e)cos(a),s cos(e)sin(a),s sin(e)]`，再以平台當前旋轉轉到世界座標。速度為零即自由落下。往中心功能使用當前起點計算 `atan2(−y,−x)`；變更 XY 後仍持續重新計算方向，手動改方位角則取消自動對準。若起點就在中心，對準功能把速度設為零。

精準投球預設起點為 (90,65) mm，高度 120 mm、方位 -145°、仰角 -15°、速度 0；底層 spawn 的一般預設高度為 180 mm，不同投球按鈕可指定不同高度。底層接受高度會限於 40～800 mm、XY 各限於 ±300 mm、世界速度各分量限於 ±3 m/s。這些是輸入保護範圍，不表示投在此範圍內就一定落在平台上。

完整工作臺的 3D 拖曳投球先由遊標射線與當前平台表面相交取得起點，允許半徑 230 mm 內選點。拖曳向量決定方向，區域性拖曳距離乘 2.5 決定速度，上限 0.85 m/s；高度固定 120 mm、仰角為零。鬆手才建立物理剛體。視覺拋物線是初始自由飛行的預覽，不預測落地後的滾動、彈跳或平台後續運動。

線衝量按鈕施加向量 `[1.2,−0.6,0.25] N·s`；角衝量按鈕施加 `[0.13,−0.1,0] N·m·s`。連續擾動為 `[15sin(3.4t),10sin(2.7t),4cos(1.9t)] N`。按鈕短標籤只顯示主分量，精確向量以此為準。

程式依據：`lib/launch.ts` 全檔；`lib/simulation.ts` 的 `spawn()`、`launch()`、`impulse()`、`tick()`；`lib/scene.ts` 的 `localPointer()`、`pointerMove()`、`pointerUp()`。

## 22 迷宮、手動挑戰與評分

### 真正有碰撞與孔洞的關卡

迷宮板不是覆蓋在原本完整平面上的圖片。載入關卡時移除原六角平台碰撞形狀，依孔洞邊線把 600×600 mm 的底板分割成互不重疊矩形，排除孔洞內的區塊；畫面與物理共用同一組 `mazeFloor()` 分割資料。牆體直接附著於上平台剛體，牆厚通常 12 mm、高 56 mm，自平台表面 Z=22 mm 向上延伸。外圍牆中心位於 XY=±190 mm，形成可玩的內部範圍；底板外緣更大以支援機構接點。牆設定零額外質量，底板各區依面積分配總平台質量。

| 關卡 | 結構 | 時限／基準時間 | 必經光圈數 |
|---|---|---|---:|
| 01 折返入門 | 兩道橫牆，左右折返 | 120／45 s | 4 |
| 02 交錯閘門 | 三道交錯直牆 | 150／60 s | 6 |
| 03 空洞之間 | 兩個 70×70 mm 真實孔洞、一段牆 | 120／45 s | 4 |

按下「開始」才重置成關卡配置並投放一球，球接觸後開始計時；備球超過 4 s 還未到達表面即判失敗。光圈必須按順序透過，透過半徑 26 mm。所有光圈完成後，球須在終點約 27 mm 內、速度低於 45 mm/s 且接觸平台，連續停留 0.6 s 才成功。掉球、急停、重播、時間重設或切換自動控制會中止當次手動成績。

### 手動搖桿如何控制

觸控搖桿與 WASD／方向鍵產生 [-1,1] 的 XY 輸入；兩種輸入合併後限幅。每 8 個物理步將目標設為 `[0,0,0.48,−y·4.5°,x·4.5°,0]`，使用 0.1 s 姿態過渡，並關閉自動置中。放開搖桿會回到水平命令，球仍保留慣性；要煞車應提前反向傾斜，而不是等待球到達目標才放手。

### 四項挑戰

置中衝刺：球起於 (115,-85) mm，時限 60 s、基準 16 s，目標為原點。精準停球：相同起點，目標 (-100,100) mm，時限 75 s、基準 24 s。兩者均需在目標 15 mm 內、速度低於 25 mm/s、接觸並持續穩定 0.8 s。

海浪生存：維持球在半徑 180 mm 安全圓內 30 s。底座擾動為 Z=`9sin(1.1t)` mm、Roll=`0.035sin(0.8t)` rad、Pitch=`0.028sin(0.65t)` rad，玩家手動調整平台。這與工程 SEA COMP. 的自動世界水平補償不同；工程海浪振幅為 Z=16 mm、Roll=0.075 rad、Pitch=0.06 rad。

節能控制使用相同起點與固定機構，目標位於 (-70,65) mm。球接觸台面、距光圈中心小於 15 mm 且球速小於 25 mm/s，連續達 1.2 s 即完成。45 秒內未完成或球落台時為零分。挑戰初始化會校正球質量、固定 S 曲線命令輪廓，並使用沒有應用附件與額外載荷的裸機。

### 分數、獎牌與儲存

迷宮、置中衝刺與精準停球成功分數：`round(clip(1000−7·max(0,用時−基準時間)−3·接觸碰撞數,100,1000))`。海浪生存成功分數：`round(clip(1000−2200·位置RMS,100,1000))`，RMS 單位為 m。失敗為零分；850 分以上金牌、650 分以上銀牌，其餘成功為銅牌。

節能控制從起球接觸到完成，逐步累計六腿機械功率絕對值的積分，令消耗量 W 的單位為 J。成功分數為 `round(clip(20000/(20+W),100,1000))`。20 J 對應 500 分，同樣停到目標時較少的累積機械功會得到較高分。面板、成績卡與本機最佳成績會保存本輪焦耳數。這個數字描述致動器機械作功，電路靜耗與馬達效率需透過額外模型換算。

碰撞計數忽略開始後前 0.4 s 的落球衝擊，同一連續接觸需相距至少 0.16 s 才再計一次。軌跡每 16 個物理步取點，最多 2,200 點，成績結果再每三點保留一點。最佳紀錄僅在成功且高於舊分數時更新，使用瀏覽器 localStorage 的 `stewart-v2-best`。這是目前裝置的個人成績，沒有雲端排行榜、帳號同步或防作弊驗證。分享 PNG 成績卡輸出分數、時間、接觸次數與軌跡；分享關卡連結只選定關卡，不會自動匯入他人的成績或完整物理狀態。

程式依據：`lib/mazes.ts`；`lib/play-session.ts` 的 `resetWorld()`、`startMaze()`、`startChallenge()`、`newRun()`、`tick()`、`finish()`；`lib/score-card.ts`。

## 23 遙測、估算值、實驗資料與驗證工具

Full Dynamics 儀表從各套筒及活塞剛體的實際端點讀取腿長。Realtime 儀表由載台與底座姿態的 IK 幾何得到腿長。速度與加速度由相鄰物理步差分取得。姿態儀表顯示 Euler 角的變化率。馬達電流估算為 `|F|/150` A，機械功率為 `|F·v|` W，能量是功率對時間的積分。溫度模型從 24°C 開始，`dT/dt=0.018I²−0.008(T−24)`。機械功積分可比較不同指令的運動成本。插座耗電需額外加入電子損耗、馬達效率與回生模型。

歷史儀表最多保留 900 個 30 Hz 樣本，即最近約 30 s。CSV 匯出的是時間、Pitch 目標／實際度數、球 XY mm、機械能量 J 六欄，並非畫面所有資料。JSON 格式名稱是 StewartLab、格式 version 仍為 1（產品版本為 3.0），包含幾何、控制、部分物理設定、輪廓、圓周、手繪路徑、關鍵影格、結果、錄製影格與樣本。匯入會重建原點模擬並恢復合法目標；不回復 Rapier 內部接觸求解器、當前球速或完整可接續的世界快照。非所有可調狀態都有序列化，例如挑戰進度、localStorage 最佳成績、音量與攝影機偏好不是同一份實驗 JSON 的完整回復範圍。

「狀態錄製／重播」每秒儲存 30 組平台、底座、致動器與物件的狀態，最多 9,000 幀，約五分鐘。Full Dynamics 會另外保存六條連桿的實際端點與旋轉。舊版紀錄缺少連桿欄位時，可依幾何姿態重建顯示。重播會讀取已錄製的狀態。工作臺的影片錄製則會直接輸出瀏覽器可播放的影音檔。

控制器比較建立獨立的臨時 Simulation，依序測 PID、LQR、MPC，每種模擬 14 s，在相同位置 (100,-65) mm 投球，初速度 (25,15) mm/s，收集收斂時間、終值誤差、RMS、峰值、最大傾角、機械能量與是否掉球。它不改動目前主場景，但不是把所有參數一律複製：目前複製幾何、動態模式、摩擦、彈性與控制設定，其他未複製值保留新模擬預設。

頻率響應測試使用 2° Pitch 正弦命令，頻率為 0.1、0.2、0.4、0.7、1、1.5、2 Hz；每點執行 `max(8 s,3/f)`，取最後一個週期與正弦／餘弦作相關投影，估算振幅比 dB 與相位角。這是非線性模擬的一組有限振幅量測，不是完整線性系統辨識。掃頻建立獨立模擬，主要複製幾何與動態模式，未一律繼承當前所有控制／物理設定。

程式依據：`lib/simulation.ts` 的 `tick()`、`sample()`、`startRecord()`、`replay()`、`exportExperiment()`、`loadExperiment()`；`app/dialogs.tsx` 的 `runComparison()`、`runSweep()` 與訊號 CSV 下載流程。

## 24 安全狀態與重設語意

急停關閉自動控制、停止場景命令，記住當下腿長作為制動保持目標；物理模式仍可能有短暫制動動態，並非把整個世界瞬間歸零。解除急停只解除保持，等待新命令。單腿故障注入會使該腿命令速度／加速度歸零、軸向施力設為零，平台可能失穩，系統沒有自動規劃剩餘五腿容錯運動。

狀態依優先序呈現急停、致動器失效、98% 以上力飽和、條件數>100、行程餘裕<8% 或正常。行程餘裕的百分比是距最近端點除以總行程再乘 200，因此行程正中為 100%。姿態非有限值、平台 Z<170 mm，或 Roll/Pitch 絕對值超過 0.65 rad 時，系統會暫停並急停，以保留失穩現場供使用者重設。

清空球體只移除投放剛體、清除追蹤與球相關統計，保留平台姿態、場景任務及自動功能啟用狀態；循跡控制回到等待新球。全域重設重建平台與剛體世界、回到 HOME、清除球、解除急停、停止錄製／重播與自動任務。遊戲的「重新挑戰」還會套回固定遊戲參數並準備起始球。這三個操作的語意必須在檔案與介面維持一致。

| 沒有聲音 | 使用者先點音效開關，確認網頁／系統未靜音且音量不是 0；靜止或暫停時本來就較安靜 |
| 球一直滾、放開搖桿沒停 | 平台回水平不會刪掉球的動量，提前向反方向傾斜煞車 |
| 自動救球失敗 | 降低初速度、降低落球高度、從平台有效區域投球；檢查摩擦、故障、感測延遲及是否還有可追蹤球 |
| 很多球無法一起置中 | 平台只有一組共同傾斜控制，改用最新球／指定球；球群中心只控制群體中心，無法分別操控每顆球 |
| 路徑速度比設定慢 | 急彎限速、接入或加速階段是預期；比較目標速度與真實球速，不只看速度滑桿 |

| 迷宮光圈沒有算透過 | 必須按順序、球接觸地板並進入容差；終點還需速度與停留時間達標 |
| 遊戲結束後平台不動 | 成績畫面會暫停儲存結果，按再挑戰或離開關卡開始下一次 |
| 影片提前結束 | 切到背景分頁、按停止、緩衝容量上限或編碼錯誤都會結束；保留可播放片段，再以較短片長重錄 |
| 下載只有 WebM | 當前瀏覽器支援的編碼決定格式，可用支援 WebM 的播放器或自行轉檔；本系統沒有內建影片轉檔服務 |
| 載入 JSON 沒有恢復原本所有球 | JSON 還原設定與錄製畫面，不還原整個 Rapier 接觸世界，請用狀態重播檢視儲存的物件 |
| 換裝置找不到成績 | 最佳分數存在原裝置的 localStorage，沒有雲端同步，分享用 PNG 成績卡 |
| 效能變差 | 清空多餘物件、關閉透視／熱圖／錄影等額外顯示、關閉其他大量使用 GPU 的分頁；物理頻率不代表一定能即時達到指定倍速 |

## 26 驗證方法

控制艙頁底的「驗證紀錄」列有此次建置的數值結果、測試條件、瀏覽器操作與模型範圍。

`pnpm test` 以正式 Rapier 與控制器程式執行回歸。`tests/dynamics.ts` 檢查關節拓撲、IK 與 FK 是否閉合、受力反應、偏心負載、行程止擋以及球體自由落體。這些案例可用於相同版本與參數下的數值重現。硬體精度仍須透過實測對照。

`tests/applications.ts` 逐一啟動十三項場景，檢查目標可達、實際腿長改變與遙測有限。測試比較光纖峰值與偏離位置功率、對接偏心與允許進給的門檻，也檢查共振時的放大及提高阻尼後的下降。測試使用公開操作輸入，並確認切換場景會保留球體與手動控制權。

`tests/worlds.ts` 以相同的物理步長和首頁控制流程檢查十三個情境的共用狀態、單位、識別碼與急停。鐵路案例核對速度、里程及曲率積分；另對四個交通與地震案例做逐軸比對。下表列出版本 3.1 預設機構的一次回歸結果。角度取自各情境和實際載台，地震量測另由 Rapier 的兩個剛體位置獨立投影到滑軌方向。急停及暫停案例會核對四個情境的時鐘、路徑指令與制動目標。

| 情境 | 測試輸入 | 模擬量測 |
|---|---|---|
| 飛行 | 壓桿依序設為 +80% 及 −80%，俯仰同向設為 65%，各維持 3.5 秒 | 右傾機身／台面為 +8.18°／+8.09°，左傾為 −6.12°／−6.11° |
| 賽車 | 向右走線、油門 +85% 維持 3.5 秒，再向左走線、煞車 −85% 維持 6 秒 | 車速從 31.38 降到 10.18 m/s，後段台面橫滾峰值 4.13° |
| 海事 | 浪向 +45%、浪高 +75%，取第 2 至 11 秒 | 船體／台面合成傾角 RMS 為 3.373°／0.348°，底座升沉峰值 16.18 mm，單腿相對校正長度最大偏移 45.63 mm |
| 地震 | 順滑軌激振，震幅控制盤 +80%，運行 9 秒 | 試體相對位移峰值 13.540 mm，九層模型屋頂相對地基峰值為放大後的 1.219 m |

同一套物理引擎的十秒掃頻測試中，0.512 Hz 時量得位移倍率 1.33，接近 1.02 Hz 的固有頻率時達 5.49。將阻尼比從 0.096 增至 0.20，倍率降到 2.83。在地震案例中，沿滑軌激振的試體相對位移 RMS 為 5.752 mm，轉為垂直於滑軌的震向時為 0.004 mm。這些是預設縮尺機構的模擬讀數。

`tests/multiball.ts`、`tests/launch.ts`、`tests/circle.ts` 和 `tests/v2.ts` 涵蓋多球追蹤、投球向量、圓周與手繪路徑、真實孔洞、迷宮和四種挑戰。節能控制另檢查功積分、穩定保持時間、逾時歸零和重試。通關測試透過遊戲本身的手動控制輸入導引球體。

瀏覽器測試另外核對桌面與窄螢幕布局、3D 貼圖、手勢與鍵盤、情境切換與清空行為。裝置畫面更新率、瀏覽器影音編碼格式和喇叭聽感都依執行環境而異。

## 27 文件同步與開發維護

### 唯一內容來源

正式原稿是 `docs/system-manual.md`，檔案版本與日期在 `docs/manual-meta.json`。`pnpm docs:build` 從這兩個檔案產生 `public/docs/index.html`、`stewart-playground-manual.pdf` 與 `stewart-playground-manual.md`。`public/docs/manual-manifest.json` 儲存來源與輸出的 SHA-256 雜湊，不手動改寫產生成品。

PDF 產生器需要 Python 3.10 以上、reportlab 與可讀的 CJK TrueType 字型。Windows 預設使用微軟正黑體，字型僅在產生檔案時讀取，網站模擬本身不依賴 Python。需要替換執行檔或字型時使用以下方式：

```powershell
$env:STEWART_DOCS_PYTHON = '完整的 Python 執行檔路徑'
pnpm docs:build
# 其他系統也可指定相容的 CJK TrueType 字型
pnpm docs:build --font '/path/to/font.ttf' --bold-font '/path/to/bold.ttf'
pnpm docs:check
```

首次準備檔案工具可使用 `python -m pip install reportlab`。一般玩家執行已建置的網頁只需要 Node.js；下載閱讀手冊只需要 PDF 閱讀器或瀏覽器。

### 每次功能異動的必要步驟

1. 修改 HEXAMOTION 原始碼並執行相關功能驗證。
2. 同步修改手冊內實際受影響的章節、數值表、操作路徑與限制，不只新增摘要。
3. 更新檔案版本、日期及版本紀錄。內部重構亦記錄使用行為是否改變。
4. 執行 `pnpm docs:build`，檢查 PDF 中文、表格、目錄和頁面，並確認網頁下載入口。
5. 執行 `pnpm docs:check`、所需測試與 `pnpm build`，將程式、原稿及下載成品一起提交和部署。

`pnpm build` 會先執行文件同步檢查。如果受監控的程式、套件、檔案或生成器變更，而尚未重新產生檔案，建置會停止並列出檔名。這項檢查可以發現遺漏更新或舊下載檔；它無法自動理解文字是否正確，仍需維護者依實際行為審閱。
